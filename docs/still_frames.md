# Still frames from arcosim

## Intent

Produce a single PNG frame from a scenario run so the project can
illustrate itself with its own renderer output: a website card, a README
header, a release asset. Before this feature the only file `arcosim` could
write was an MP4, at a framebuffer size fixed at 1280 x 720, so any still
had to be cut out of a lossy video at the wrong resolution.

`docs/VISUALIZATION.md` previously documented `arcosim --image` and
`arcosim --static` for this. Neither flag was ever implemented in
`src/arco/simulator/__main__.py`; the matplotlib layer under
`src/arco/simulator/viewer/` has no CLI entry point. That documentation is
corrected in the same change that adds the feature below.

## Scope

In scope:

- A `--still` flag on `arcosim` that saves selected recorded frames as PNG.
- `--width` / `--height` so a still can be produced at a size other than
  the recording default, for example 1920 x 1080.
- A `--seed` flag that pins otherwise unseeded planner sampling so a still
  can be regenerated byte-for-byte.
- All four scenarios: `city`, `ppp`, `rrp`, `occ`.

Out of scope:

- Any change to the default recording path. With no `--still` the CLI
  behaves exactly as before, including the 1280 x 720 (ppp/rrp: 1280 x 800)
  recording size and the MP4 encoder, so `scripts/generate_videos.sh` and
  the release workflow are unaffected.
- A chrome-free viewport. `ScreenLayout` composes header, sidebar and
  footer into every scenario and there is no mode that omits them; a still
  therefore carries the same chrome as a release video.
- Threading a planner seed through the scene classes. `--seed` pins the
  process RNG instead; see [Design notes](#design-notes).

## Acceptance criteria

| Id | Criterion |
|---|---|
| AC-STILL-01 | When `--still` names one frame index and `--output` ends in `.png`, the system shall write exactly that file. |
| AC-STILL-02 | When `--still` names several frame indices, the system shall write one file per index, suffixed `_fNNNNN`. |
| AC-STILL-03 | When `--width` and `--height` are given with `--still`, the system shall render the frame at exactly those pixel dimensions. |
| AC-STILL-04 | When `--still` is absent, the system shall resolve the recording size from the scenario defaults and write an MP4, unchanged from before this feature. |
| AC-STILL-05 | When the scenario ends before the highest requested frame index, the system shall fail with a message naming the missing indices rather than writing a partial set silently. |
| AC-STILL-06 | When `--seed` is given, the system shall make unseeded `numpy.random.default_rng()` calls deterministic while leaving calls that pass an explicit seed untouched. |
| AC-STILL-07 | The saved PNG shall be 8-bit RGB with no alpha channel. |

## Traceability

Ids follow `AC-STILL-NN`. Tests reference them in the test name or in a
comment so the mapping is greppable both ways.

## Constraints

- No new runtime dependency. Frames are written through `pygame.image.save`,
  already required by the `tools` extra.
- The still path must not alter simulation state. It replaces the frame
  sink and the framebuffer size, nothing else.
- Scenario YAML under `map/` and the palette under `src/arco/config/` are
  read-only for this feature.

## Design notes

`arco.simulator.sim.still` holds a process-level `StillRequest`. The CLI
sets it when `--still` is given; the scenario mains consult it through two
helpers:

- `resolve_recording_size(default_w, default_h)` returns the request's
  size, or the passed defaults when no request is active.
- `make_writer(path, width, height, fps)` returns a `StillSink` when a
  request is active and a `VideoWriter` otherwise.

`StillSink` matches the `VideoWriter` method surface (`open`, `close`,
`write_frame`, `write_frame_gl`, context manager) so the mains need no
branching beyond those two calls. It raises `CaptureDone` once the last
requested frame is saved, which unwinds the render loop through its
existing `finally` block.

`--seed` wraps `numpy.random.default_rng` in the CLI layer rather than in
a library module. The scene classes build `RRTPlanner` / `SSTPlanner`
without passing a seed, so there is no parameter to set; wrapping the
factory is the smallest change that makes a run repeatable. Threading an
optional `planner.seed` through the scenes would be the cleaner fix and is
left as follow-up work.
